# 阿里云采集端中控对接改造待办清单

## 1. 文档说明

- 项目：`aliyun-data-collector`
- 当前分支：`jdk-8`
- 当前版本：`0.1.2-SNAPSHOT`
- 目标：在保留现有现场离线采集能力的基础上，将项目改造成可部署于私有云 Kubernetes 集群、持续轮询 ARMS/SLS、通过文件式 Outbox 向 `cc-ingest` 主动批量推送数据，并可主动领取中控任务的常驻采集服务。
- 使用方式：完成一项后，将对应的 `- [ ]` 修改为 `- [x]`，并在“完成记录”中填写日期、提交号和验证结果。

状态说明：

- `[ ]`：未开始或未完成。
- `[x]`：已经完成并通过该项完成标准。
- 不建议仅因代码已经编写就标记完成；至少应完成对应测试或人工验证。

## 2. 当前已具备的基础能力

- [x] 支持 ARMS RPC 只读采集。
- [x] 支持 ARMS Dataset 只读采集。
- [x] 支持 SLS Project、Logstore 和日志分页采集。
- [x] 对 ARMS 动作实施代码层只读白名单。
- [x] 支持按指定开始时间和结束时间分窗采集。
- [x] 支持 ARMS Trace 搜索及 Trace 详情采集。
- [x] 支持原始响应写入 `raw/arms` 和 `raw/sls`。
- [x] 支持 `.partial` 临时文件和完成后的原子移动。
- [x] 支持 manifest、文件大小、SHA-256 和 Request ID。
- [x] 支持按页面、Trace 详情和任务窗口断点续采。
- [x] 支持输出完整性校验和辅助 manifest 重建。
- [x] 凭据只从环境变量读取，可由 Kubernetes Secret 注入。
- [x] 保留 `collect`、`resume`、`probe`、`discover` 等现场命令行能力。

## 3. 推荐实施顺序

```text
统一协议与配置
    → 标准事件转换
    → 增量水位与常驻调度
    → 文件式 Outbox
    → 组批与主动上传
    → COMMITTED 回执与上传检查点
    → 控制任务、心跳和健康检查
    → Kubernetes 部署
    → 故障、安全和现场验收
```

### P0-07 实现组批策略

- [ ] 按最多 1000 条事件结束当前批次。

- [ ] 每个批次生成独立且稳定的 `batch_id`。
- [ ] 批次重试不得重新生成 `batch_id`。
- [ ] 组批过程中不得把整轮结果全部保存在内存中。
- [ ] 增加记录数、压缩大小、尾批、超大单条事件和确定性批次 ID 测试。

- [ ] 新增 `UploadCheckpointStore`，不得复用采集页面 checkpoint。

### P0-10 解耦采集线程和上传线程

- [ ] 采集线程只负责查询、raw 落盘、标准化和写入 Outbox。
- [ ] 上传线程只负责读取 Outbox、提交 Ingest 和处理回执。
- [ ] `cc-ingest` 不可用时，ARMS/SLS 采集可以继续运行，直到触发磁盘高水位策略。

- [ ] 限制上传线程内存和并发，避免恢复网络后瞬间压垮 Ingest。
- [ ] 增加慢上传、Kafka不可用、持续积压和恢复追赶测试。

完成标准：关闭 `cc-ingest` 30分钟后恢复，采集端能够继续采集、保留数据并按顺序补传，无进程崩溃和文件丢失。

### P0-11 实现采集端身份和 mTLS

- [ ] 私钥和信任库通过只读 Secret Volume 挂载，不写入镜像、Git或普通日志。
- [ ] 配置证书到期时间检查和告警。
- [ ] `collector_id` 与证书身份由 Ingest 服务端绑定校验，不能只信任请求体。
- [ ] 日志只记录证书指纹和到期时间，不记录私钥或完整令牌。
- [ ] 验证无证书、错误证书、过期证书、错误 collectorId 和证书轮换场景。

完成标准：未授权采集端无法上传数据；合法证书轮换时不需要重建业务数据或清空 Outbox。

## 10. 变更约束

- 保留原始响应、manifest、SHA-256、输出校验和断点续采能力，不因接入中控而删除离线模式。
- 采集端主动推送数据、主动领取控制任务；中控不主动访问采集Pod。
- 采集端不直接访问Kafka、数据库和三个研究服务。
- AccessKey不得由中控下发，不得写入YAML、镜像、Git、manifest或日志。
- 原始数据必须先可靠落盘，再进入标准化和上传流程。
- 未收到`COMMITTED`前不得删除或标记上传批次成功。
- 任何自动删除、降级或扩大采集范围的行为都必须有明确策略和审计记录。
